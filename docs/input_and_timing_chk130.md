# chk130：角色选择输入与跨帧差分追踪（2026-09-23）

## 已核实的时序范围

在相同环境和排除名单下运行 200 帧，分别设置 SNESRECOMP_LLE_BOUNCE=1/0，
使用现有 SNESRECOMP_WLOG_ADDR=000E:000F:<path>、SNESRECOMP_WLOG_STATE=1、
SNESRECOMP_WLOG_ADDR_CAP=150000 记录写入。此前脚本第 360 帧才开始按键，故这段探针无需输入。

AOT 记录 56222 条，bounce-off 记录 56218 条，没有触及上限。
两份记录的共同前缀中，写入地址、值、寄存器状态和归属 PC 完全一致。
首个记录差异在零基索引 18450：同一条 $84:E1B7 对 $000E 写入 $54，
AOT 发生于 f185，bounce-off 发生于 f186。AOT 最后多四条字节写入。
因此 f200 的 $000E 不同至少包含解压进度跨帧偏移；本结论仅覆盖 $000E-$000F 的追踪，
不证明其他内存、硬件状态或整个执行序列一致。

详见 artifacts/chk130-wram/analysis.json 及两个 writes.log。
生成器 emit_function.py 仍按代码区域速度为整块 CPU 周期计费，而解释器按实际总线访问和内部周期计费。
尚未定位整条路线的全部时钟差异；本轮没有再改周期常数、栈掩码、排除名单或 generated C。

## 输入调查与修改

默认 Y+START 脚本和仅 P1 B 脉冲脚本，最终均为 mode=0/state=6，
$70=2、$72=0、$96=0。ROM $85:965B 明确检查两个确认状态都为 2 后才计数推进。
旧工程中额外的 P2 自动确认补丁不属于本 ROM 原始逻辑，未移植该补丁。

headless.c 输入解析新增 P1_、P2_ 前缀，例如 1020:P2_B。
未加前缀仍是 P1；P2 使用 RtlRunFrame 已支持的高 12 位输入。
只有输入主机发生变化，没有直接写入游戏确认状态。

ROM $85:94A2 优先判断 P1 确认键：两人同时按 B 时只处理 P1，故同时按键的实验
依然停留角色选择。下一项实验把 P2 按键错开 60 帧。
反汇编记录：artifacts/chk130-menu/rom-confirm-disassembly.txt。

validate_migration.py 的脚本帮助已更新；使用手柄前缀必须显式跳过尚未核实支持此格式的旧主机。
现有门槛测试 5/5 通过；不支持的跨主机组合在启动游戏前被拒绝。

## 错开手柄确认的实测结果

新 EXE 已编译，SHA256：b9d6dc0da6fbb271966e81be0ca24880c7138b2691b1642d3857f97b5504543d。
脚本为 `360:B,480:B,600:B,720:B,840:B,960:B,1080:B,1200:B,1320:B,1020:P2_B,1140:P2_B,1260:P2_B,1380:P2_B`。

- f1000：P1=1，P2=0；f1100：P1=2，P2=1。
- f1200：两者均为 2，过渡计数 60。
- f1260 起：state=8，角色选择已自然退出；f1330 pending=2。
- f1400：mode=0/pending=2/state=0，最终截图为黑屏过渡；进程正常退出。

这证明双手柄输入与错开确认能解除当前角色选择阻塞，不证明已经进入可驾驶比赛。
